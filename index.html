Fase 1: Pensamiento Computacional en Scratch Puro

Antes de soldar o conectar componentes electrónicos, modelamos la lógica de ecolocalización. Un murciélago emite chasquidos ultrasónicos y mide el desfase temporal del eco para deducir distancias. En Scratch, programamos esta secuencia lógica mediante eventos, bucles de ejecución continua y condicionales de proximidad.

Algoritmo del Sistema Murciélago

  1. Evento de Inicio: Inicializar variables (umbral = 15, alerta = 0).
  2. Bucle Infinito (Por siempre): El robot o murciélago avanza y realiza un muestreo continuo del entorno.
  3. Sensado: Medir la distancia acústica hasta el obstáculo más cercano.
  4. Decisión Lógica (SI... ENTONCES... SI NO):
    • Si distancia < 15 cm: Activar advertencia luminosa (disfraz o color rojo), emitir tono sonoro y frenar avance.
    • Si no: Mantener avance, silenciar alertas y mostrar estado de patrulla segura.
Principio STEM Clave: La computadora no "ve" el obstáculo directamente; calcula una magnitud física (tiempo de propagación) y ejecuta una comparación aritmética (distancia < 15).

¿Por qué una resistencia de 220 Ω?

Por la Ley de Ohm: \(I = \frac{V_{CC} - V_F}{R} = \frac{5V - 2.0V}{220\,\Omega} \approx 13.6\text{ mA}\). Protege el puerto ATmega328P de superar el límite térmico seguro (20 mA por pin) e impide la destrucción irreversible del LED.

Fase 4: Transición al Hardware Real y Código C++

Código fuente C++ íntegro del proyecto arduino_led_buzz_murcielago.txt, listo para compilar en el IDE de Arduino y transferir a la placa física mediante cable USB.

arduino_led_buzz_murcielago.ino / .txt 
/*
 * =====================================================================
 * PROYECTO: Sistema Murciélago (Ecolocalización con HC-SR04)
 * AULA DE ROBÓTICA - TINKERCAD CIRCUITS & ARDUINO UNO R3
 * Archivo fuente: arduino_led_buzz_murcielago.txt / .ino
 * =====================================================================
 * Conexión de Patillaje:
 *   - HC-SR04 TRIG -> Pin Digital 13 (Azul)
 *   - HC-SR04 ECHO -> Pin Digital 12 (Verde)
 *   - HC-SR04 VCC  -> 5V (Rojo)
 *   - HC-SR04 GND  -> GND Común (Negro)
 *   - LED Alarma   -> Pin Digital 5 (Ánodo) con Resistencia 220 Ω a GND
 *   - Zumbador (+) -> Pin Digital 7 (Morado) y Negativo a GND
 * =====================================================================
 */

// 1. Constantes de hardware y definición de pines
const int PIN_TRIG   = 13; // Disparador pulso ultrasónico
const int PIN_ECHO   = 12; // Receptor pulso ultrasónico
const int PIN_LED    = 5;  // LED de advertencia luminosa
const int PIN_BUZZER = 7;  // Zumbador piezoeléctrico acústico

// 2. Parámetros de calibración física
const int UMBRAL_DISTANCIA = 15; // Distancia límite en centímetros
long duracion_eco = 0;           // Tiempo de vuelo en microsegundos
float distancia_cm = 0.0;        // Distancia calculada

void setup() {
  // Inicialización de la telemetría por puerto serie a 9600 baudios
  Serial.begin(9600);

  // Declaración del sentido de flujo de los pines (I/O)
  pinMode(PIN_TRIG, OUTPUT);
  pinMode(PIN_ECHO, INPUT);
  pinMode(PIN_LED, OUTPUT);
  pinMode(PIN_BUZZER, OUTPUT);

  // Inicializar actuadores en estado de reposo (BAJO)
  digitalWrite(PIN_TRIG, LOW);
  digitalWrite(PIN_LED, LOW);
  digitalWrite(PIN_BUZZER, LOW);

  Serial.println(F("================================================"));
  Serial.println(F(" [OK] SISTEMA MURCIÉLAGO HC-SR04 INICIALIZADO"));
  Serial.println(F(" Umbral de Proximidad Configurado: 15 cm"));
  Serial.println(F("================================================"));
  delay(200);
}

void loop() {
  // PASO 1: Generar tren de pulso limpio en pin TRIG
  digitalWrite(PIN_TRIG, LOW);
  delayMicroseconds(4);
  digitalWrite(PIN_TRIG, HIGH);
  delayMicroseconds(10); // Pulso de excitación estándar de 10 microsegundos
  digitalWrite(PIN_TRIG, LOW);

  // PASO 2: Medición del tiempo que tarda el eco en regresar
  // Timeout de 30000 µs (~5 metros) para evitar bloqueos del procesador
  duracion_eco = pulseIn(PIN_ECHO, HIGH, 30000);

  // PASO 3: Cálculo cinemático de la distancia
  // Velocidad del sonido en aire seco a 20°C: 343 m/s = 0.0343 cm/µs
  // Trayecto ida y vuelta: distancia = (tiempo * 0.0343) / 2
  if (duracion_eco == 0) {
    distancia_cm = 400.0; // Fuera de rango o sin eco reflejado
  } else {
    distancia_cm = (duracion_eco * 0.0343) / 2.0;
  }

  // PASO 4: Salida de telemetría al Monitor Serie
  Serial.print(F("Distancia: "));
  Serial.print(distancia_cm, 1);
  Serial.print(F(" cm | Estado: "));

  // PASO 5: Lógica de control y disparo de actuadores
  if (distancia_cm > 0 && distancia_cm <= UMBRAL_DISTANCIA) {
    // CONDICIÓN CRÍTICA: Obstáculo a menos de 15 cm
    digitalWrite(PIN_LED, HIGH);        // Enciende LED de alarma
    tone(PIN_BUZZER, 1200);             // Frecuencia sonora penetrante (1200 Hz)
    Serial.println(F("[¡ALERTA OBSTÁCULO!] -> LED: ON | BUZZER: ON"));
  } else {
    // CONDICIÓN SEGURA: Vía libre
    digitalWrite(PIN_LED, LOW);         // Apaga LED de alarma
    noTone(PIN_BUZZER);                 // Silencia zumbador
    Serial.println(F("[VÍA LIBRE] -> LED: OFF | BUZZER: OFF"));
  }

  // Cadencia entre lecturas para estabilización de ecos (100 ms = 10 Hz)
  delay(100);
}

¿Por qué dos Mini-Protoboards en el Chasis Real?

En el diseño de robots móviles educativos (chasis acrílicos 2WD/4WD), se recomienda distribuir el hardware en dos mini-placas de prototipos independientes en lugar de una protoboard única:

  • Mini-Protoboard Frontal (Etapa de Sensado): Aloja exclusivamente el sensor HC-SR04 en la proa del robot, libre de obstáculos visuales y a la altura óptima del suelo.
  • Mini-Protoboard Superior (Etapa de Potencia/Señal): Aloja el LED de alarma, la resistencia y el zumbador piezoeléctrico junto a la controladora Arduino.
  • Desacoplo de Ruido Electromagnético: Los transitorios inductivos y mecánicos del zumbador no meten ruido en la línea de disparo del sensor ultrasónico.
  • Modularidad: Facilita sustituir módulos dañados en el aula sin desmontar todo el cableado del robot.

El "Simulation Gap" (Simulador vs Realidad)

El software de simulación asume condiciones ideales que no siempre se cumplen en la mesa de trabajo:

  • Cono Acústico de 15° y Reflexión Especular: En Tinkercad cualquier objeto refleja el sonido perfectamente. En el aula, si un obstáculo está inclinado más de 15° o es de tela/gomaespuma, el sonido se dispersa y el sensor devuelve 0.
  • Bloqueo por pulseIn() sin Timeout: Si se omite el tercer parámetro de timeout (30000), la función bloquea el microcontrolador durante 1 segundo entero ante pérdidas de señal.
  • Caídas de Tensión (Brownout): Al activar simultáneamente el LED y el zumbador en un puerto USB débil, la tensión puede caer de 5.0V a 4.6V, alterando el umbral de disparo acústico.
